# 任务描述（description.md）共创指南

## 概述

`description.md` 是任务的详细描述文档，用于：
1. 帮助 Claude 理解任务背景，生成更合适的代码
2. 后续转换为 `task.goal` 文件驱动 AlphaEvolve 进化

## 文件格式

Markdown 格式，包含以下核心部分。

## 核心要素

| 要素 | 说明 | 必填 |
|------|------|------|
| 任务背景 | 业务/研究场景 | ✅ |
| 数据说明 | 数据结构和特点 | ✅ |
| 优化目标 | 要优化的指标 | ✅ |
| 约束条件 | 限制和要求 | 推荐 |
| 改进方向 | 可能的优化方向 | 可选 |

## 模板

```markdown
# [任务名称]

## 任务背景

[描述业务/研究场景，说明为什么要做这个任务]

## 数据说明

### 训练数据 ([实际文件名，如 training_data.parquet])
- 行数：[N] 行
- 特征列：[列出主要特征及其含义]
- 目标列：[目标列名称及含义]

### 测试数据 ([实际文件名，如 validation.csv])
- 行数：[N] 行
- 结构与训练数据相同

### 数据特点
- [描述数据的特殊之处，如类别不平衡、缺失值、时序特性等]

## 优化目标

主要指标：[指标名称]，[越大/越小]越好

次要指标（可选）：
- [指标1]
- [指标2]

## 约束条件

- [约束1，如：不能使用某些库]
- [约束2，如：运行时间限制]
- [约束3，如：内存限制]

## 改进方向（可选）

- [方向1，如：尝试特征工程]
- [方向2，如：尝试不同模型]
- [方向3，如：超参数调优]
```

## 共创流程

### 当用户没有 description.md 时

**步骤 1：收集基本信息**

询问用户：
```
为了生成高质量的代码，请告诉我：

1. **任务背景**：
   您在做什么业务/研究？这个预测/分类有什么用途？

2. **目标列确认**：
   根据数据分析，目标列是 [X]，这是正确的吗？

3. **优化指标**：
   您希望优化什么指标？
   - 回归任务常用：RMSE、MAE、MAPE、R²
   - 分类任务常用：准确率、F1、AUC

4. **有什么约束吗？**（可选）
   - 运行时间/资源限制？
   - 不能使用的方法？
   - 其他要求？
```

**步骤 2：生成初稿**

根据用户回答和数据分析结果，生成 description.md。

**步骤 3：确认并写入**

展示生成的内容，用户确认后写入文件。

### 当用户已有 description.md 时

1. 阅读现有内容
2. 检查是否包含所有核心要素
3. 如有缺失，提出补充建议
4. 用户确认后更新

## 示例

### 回归任务示例

```markdown
# 大豆产量预测

## 任务背景

农业研究项目，需要根据气象数据和种植信息预测大豆产量，帮助农户做出种植决策。

## 数据说明

### 训练数据 (train.csv)
- 行数：5000 行
- 特征列：
  - month: 月份 (1-12)
  - state: 州/地区
  - temperature: 平均温度
  - precipitation: 降水量
  - soil_moisture: 土壤湿度
- 目标列：yield（产量，连续数值）

### 测试数据 (test.csv)
- 行数：1000 行
- 结构与训练数据相同

### 数据特点
- 存在时序特性（月份影响产量）
- 不同州之间产量差异大
- 部分气象数据存在缺失

## 优化目标

主要指标：RMSE（均方根误差），越小越好

次要指标：
- MAPE（平均绝对百分比误差）
- R²（决定系数）

## 约束条件

- 必须在测试集上评估
- 预测值必须为非负数

## 改进方向

- 时序特征：利用月份周期性
- 交叉特征：州与气象的交互
- 集成方法：模型融合
```

### 分类任务示例

```markdown
# 客户流失预测

## 任务背景

电信公司希望预测哪些客户可能流失，以便提前采取挽留措施。

## 数据说明

### 训练数据 (train.csv)
- 行数：8000 行
- 特征列：
  - tenure: 客户在网时长
  - monthly_charges: 月消费额
  - total_charges: 总消费额
  - contract: 合同类型
  - payment_method: 支付方式
- 目标列：churn（0=不流失，1=流失）

### 数据特点
- 类别不平衡：流失客户约 25%
- 存在类别特征需要编码
- 部分数值特征分布偏斜

## 优化目标

主要指标：AUC，越大越好

次要指标：
- F1-score
- Recall（召回重要，不想漏掉流失客户）

## 约束条件

- 预测概率必须在 [0, 1] 范围内
- 关注少数类（流失客户）的识别

## 改进方向

- 处理类别不平衡：SMOTE、类别权重
- 特征工程：消费行为特征组合
- 模型选择：XGBoost、LightGBM
```
